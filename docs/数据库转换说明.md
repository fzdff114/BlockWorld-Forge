# Atlas 0.3.0 — Bedrock 数据库转换实现

## 参考开源项目

- osm-to-bedrock（MIT）：现实坐标投影、地表填充、区块写入和 mcworld 打包的完整转换管线。
- Arnis：现代 Bedrock 调色板与子区块 v9 编码参考。
- HiveGamesOSS/leveldb-mcpe-java（Apache-2.0）：Java LevelDB 实现，支持 MCPE 使用的 ZLIB（0x02）和 ZLIB_RAW（0x04）压缩。Atlas 明确使用 ZLIB_RAW。

本实现以这些项目公开的格式结构作为参考，使用 Kotlin 在 Android 端实现写入，不调用网页服务来转换世界。

## Bedrock 世界结构

.mcworld 是 ZIP 包，根目录包含 levelname.txt、level.dat 和 db/。其中 db/ 是 LevelDB 数据库目录，并不是单独一个 .db 文件。

level.dat 文件由 8 字节小端头（StorageVersion、NBT 长度）和小端 NBT 负载组成。本版使用 StorageVersion 10。

## 区块键值

Overworld 区块键使用小端编码：

- [chunkX:int32][chunkZ:int32][0x2B]：Data3D，高度图与生物群系数据。
- [chunkX:int32][chunkZ:int32][0x2C]：区块版本，本版写入 41。
- [chunkX:int32][chunkZ:int32][0x2F][subChunkY:int8]：子区块数据，本版子区块格式为 v9。
- [chunkX:int32][chunkZ:int32][0x36]：FinalizedState，值为小端 int32 的 2。

子区块按 16×16×16 存储，方块索引采用 XZY 顺序。每层写入 palette bit header、紧凑索引字、调色板数量和小端 NBT 方块状态。

## 比例与高程

用户设置的比例为水平米/方块：1:4 即 4 米映射为 1 个方块。地理区域经纬度范围按 equirectangular 方式映射到 X/Z 网格。

20×20 高程样本通过双线性插值（缺失格点用最近有效样本补齐）得到地表高度。为限制基岩版垂直高度，垂直米/方块会取用户水平比例与最大海拔 / 280 的较大值；因此极高海拔地区会被垂直压缩。

基础地表由基岩、石头、泥土、草方块组成；负海拔区域加沙底和水层。当前没有道路、建筑、植被、洞穴、群系或遗迹生成。

## 校验

导出前后执行：

1. 检查 level.dat 的 StorageVersion 与 NBT 长度。
2. 关闭 LevelDB 后重新打开，核对区块版本键与子区块 v9 记录。
3. 打开 ZIP 并检查 level.dat、levelname.txt、db/CURRENT 和 db/MANIFEST-*。
4. CI 执行区块键、子区块头、level.dat 头和 LevelDB 压缩读写单元测试。

数据库格式校验成功不等于已完成 Minecraft 真机导入认证；仍需在目标 Android 版 Minecraft 中打开世界实测。
