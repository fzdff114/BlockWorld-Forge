# BlockWorld-Forge / Atlas

Android 原生地图采集与 Minecraft Bedrock 世界生成工具。无需 Google Play 服务。

当前版本：**0.4.4（预发布）**

## 0.4.4 更新
- **直接读取地图底图建筑**：采集时通过 MapLibre 查询当前视口中已渲染的 OpenFreeMap Liberty `building` / `building-3d` 图层，不再只依赖 Overpass。
- **读取建筑高度属性**：优先采用矢量瓦片 `render_height` / `render_min_height`，缺失时读取 `height` / `building:levels`，并保留来源。
- **三源合并**：中国逐栋数据优先，其次地图底图矢量建筑，最后 OSM Overpass 补充；合并时按建筑中心位置去重。
- **显示分源数量**：采集结果分别显示底图、中国导入、OSM 三类建筑数量。若底图当前没有加载选区瓦片，会提示缩放至建筑可见的街区级别后再采集。

## 0.4.3 更新
- **现实垂直比例修正**：地形 Y 轴以当前选区最低高程为本地基准，不再使用绝对海拔除以垂直比例；高原地区的小幅高差不会再被错误压扁。
- **默认真实比例**：新项目默认 1×，水平和垂直使用相同的米/方块比例；只有选区高差超过 Bedrock 高度范围时才自动压缩，并在导出报告显示实际垂直米/方块。
- **真实海平面**：水位使用 0 m 海拔换算到本地 Y 坐标，不把选区最低点误认为海平面。
- **中国逐栋建筑高度导入**：在“素材与建筑数据”页导入 Shapefile ZIP，支持逐栋 polygon 和 height（米）字段；当前优先数据源为 3D-GloBFP（中国按省份组织，CC BY 4.0）。
- **建筑数据优先级**：导入的中国建筑轮廓/高度优先于 OSM；按建筑中心点去重；导入图层的来源与许可归属会写入 .mcworld 的 atlas_attribution.txt。
- **格式检查**：新增 WGS84 / Web Mercator 坐标转换与建筑高度字段解析测试。

## 使用
1. 在“地图”页圈选目标区域。两点矩形或多边形均可。
2. 若需要中国逐栋建筑：先打开“素材与建筑数据”，导入选区对应省份/城市的 Shapefile ZIP。
3. 返回“地图”页，把选区缩放到能看清楼块的街区级别，等待建筑图层显示后点击“采集地形+地图建筑”。程序会读取当前视口已渲染的 OpenFreeMap 建筑矢量，再合并中国导入数据与 OSM。
4. 点击“存为项目”，选择水平比例（1:1、1:2、1:4、1:8、1:16）。新项目默认垂直 1×。
5. 进入“导出”，生成并保存 .mcworld，再用 Minecraft Bedrock 打开。

## 中国建筑数据来源与导入格式

### 推荐：3D-GloBFP
- 研究团队：中山大学等单位的研究团队。
- 内容：逐栋建筑 footprint polygon + 估算建筑高度（米），数据年份为 2020。
- 中国数据按省份组织，文件名以省份名和 CN 标识。
- 许可证：CC BY 4.0。导出世界会保留来源和署名信息。
- 数据页面：https://doi.org/10.5281/zenodo.15459025
- 项目分卷下载页由数据包中的 data_links.txt 指向；不要下载整个数十 GB 的全球合包，只准备当前省份/城市对应的 Shapefile 图层。

导入时，把同一图层的 .shp、.dbf、.shx、.prj 文件放在同一个 ZIP 中。必须带有可识别的 height / height_m 等建筑高度字段（单位米）。导入器读取当前选区边界内的记录，最大写入 20,000 栋；ZIP 解压总量上限 1.5 GB。支持经纬度坐标（WGS84 / CGCS2000）和 Web Mercator（EPSG:3857）。其他投影请先在 QGIS 中另存为 EPSG:4326。

### 中国十城建筑高度数据（2018）
国家地球系统科学数据中心还收录了北京、长沙、成都、杭州、南京、上海、沈阳、天津、武汉、西安十城的建筑足迹级高度 Shapefile 数据。页面：https://www.geodata.cn/main/face_science_detail?guid=135869909769675
该数据页介绍约 194.77 MB、超过百万栋估算建筑，但页面没有明确展示与 3D-GloBFP 相同的 CC BY 许可说明；下载与再利用前请按门户的数据使用条款核对。

## 地形比例说明
- 高程来源仍为 Mapzen Terrarium DEM 瓦片（AWS Open Data）。20 m / 30 m 是应用采样间距，不代表源 DEM 在每个地区都达到该原生精度。
- 当前导出使用选区局部最低点作为 Y 轴基准；只要高差在 Bedrock 可用高度范围内，1× 就表示垂直 1 个方块代表与水平相同的米数。
- 如果一个选区的真实高差超出 Bedrock 高度上限，程序会自动压缩垂直比例；导出状态会显示实际米/方块数值。
- 3D-GloBFP 是遥感模型估算的 2020 年建筑高度，不是实时楼层测绘。原论文在 33 个子区域验证的 R² 为 0.66–0.96、RMSE 为 1.9–14.6 m，地区差异较大。
- 底图矢量读取只访问当前地图视口中已经加载并渲染的建筑瓦片；若选区超出当前屏幕或地图尚未加载该级别瓦片，需移动/缩放地图后再次采集。它不是整个全国建筑数据下载器。
- 未收录的建筑不会自动生成；OSM 仅作为补充来源。道路面层、真实河网、植被群系、洞穴和遗迹仍未完成。

## 系统要求
- Android 8.0（API 26）或更高版本。
- 不依赖 Google Play 服务。
- 大区域导出需要充足的临时存储空间。

## 本地构建
需要 JDK 17、Android SDK 35 与 Gradle 8.14.3：

```bash
gradle --no-daemon testDebugUnitTest
gradle --no-daemon assembleDebug
```
